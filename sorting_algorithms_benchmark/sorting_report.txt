SORTING ALGORITHMS PERFORMANCE COMPARISON
=========================================

Program file: sorting_comparison.py (run with: python sorting_comparison.py)
Chart file:   sorting_chart.png (created by the program when matplotlib is installed)


1. AIM
------
Implement five sorting algorithms in Python and compare their performance:
Selection Sort, Bubble Sort, Insertion Sort, Merge Sort and Quick Sort.


2. ALGORITHMS IMPLEMENTED
-------------------------
Algorithm  | Best case  | Average    | Worst case | Extra space | Stable
-----------|------------|------------|------------|-------------|-------
Selection  | O(n^2)     | O(n^2)     | O(n^2)     | O(1)        | No
Bubble     | O(n)*      | O(n^2)     | O(n^2)     | O(1)        | Yes
Insertion  | O(n)       | O(n^2)     | O(n^2)     | O(1)        | Yes
Merge      | O(n log n) | O(n log n) | O(n log n) | O(n)        | Yes
Quick      | O(n log n) | O(n log n) | O(n^2)     | O(log n)    | No

* Bubble sort uses an early-exit flag, so already sorted input takes O(n).
Quick sort uses a median-of-three pivot and an explicit stack, so sorted and
reversed input do not cause worst-case behaviour or deep recursion.


3. METHOD
---------
- Each algorithm was tested for correctness against Python's built-in
  sorted() on about 200 random lists plus edge cases (empty list, single
  element, duplicates). All five passed.
- Timing used time.perf_counter(). Each result is the best of 3 runs.
- Input sizes: 100, 500, 1000, 2000, 5000 and 20000 elements.
- Four input types: random, already sorted, reversed, and nearly sorted
  (about 2% of elements swapped).
- Selection, Bubble and Insertion sort were skipped at n = 20000 because
  they would take too long (shown as "--").

5. ANALYSIS
-----------
1. Merge Sort and Quick Sort are far faster than the other three on random
   data. They are O(n log n), while Selection, Bubble and Insertion are
   O(n^2). At n = 5000 on random data, Quick Sort was about 81x faster than
   Selection Sort and about 346x faster than Bubble Sort.

2. The quadratic sorts grow quickly. Going from n = 1000 to n = 2000 (double
   the size) roughly quadrupled their time on random data, for example
   Selection Sort went from 11.15 ms to 47.84 ms and Bubble Sort from
   23.74 ms to 123.62 ms. Merge and Quick Sort only roughly doubled.

3. Quick Sort was faster than Merge Sort in these tests (about 2.6x on
   random data at n = 5000). It sorts in place, while Merge Sort creates and
   copies many sublists.

4. Input order matters for some algorithms:
   - Bubble and Insertion Sort are very fast on already sorted input (under
     1 ms at n = 5000) because they do almost no work (O(n)).
   - Insertion Sort is the best of the simple sorts on nearly sorted data
     (33.19 ms at n = 5000 vs 761.51 ms for Bubble and 556.68 ms for
     Selection).
   - Selection Sort has no fast case. It always scans the whole unsorted
     part to find the minimum, so it stays in the hundreds of milliseconds
     at n = 5000 for every input type (302 to 594 ms).
   - Reversed input is the worst case for Bubble and Insertion Sort
     (1695.36 ms and 1193.51 ms at n = 5000).

5. Bubble Sort was the slowest on random and reversed input because it
   performs the most element swaps.


6. CONCLUSION
-------------
Merge Sort and Quick Sort are the best choices for large or general data.
Merge Sort is preferred when a stable sort is needed or when guaranteed
O(n log n) time matters. Quick Sort is usually fastest in practice.
Insertion Sort is only suitable for small or nearly sorted lists, and
Selection and Bubble Sort are mainly useful for learning because they are
too slow on large inputs.
